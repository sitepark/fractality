# Client-render the Frame instead of server-rendering every page

Measured at issue #419's scale (3797 routable handles), **99.6% of a `dist/components/detail/*.html` is the navigation tree** — 2,516,221 of 2,527,558 bytes, leaving 11,337 for everything else on the page — and the build totals ~9.01 GB. (#419's own figures are internally inconsistent and should not be quoted: it reports 921 M total and a 782 K smallest page, but 782 K × 3797 = 2.90 GB. Cite `.scratch/client-rendered-frame/research/payload-weights.md`.) The Frame is therefore rendered client-side from JSON payloads, taking the same build to ~33.7 MB. Pure CSR was chosen over SSG + hydration, which was charted first and researched in depth before being dropped: it bought a better first paint for a _local developer tool_ at the cost of an SSR bundle, a prerender pass, hydration-mismatch discipline and a considerably harder packaging story, while the one thing it bought structurally — deep links on dumb static hosts — is bought just as well by copying a 998-byte shell to every route path, which is a file copy rather than a render pass and leaves today's URLs and bookmarks intact. Hash routing was rejected because it breaks every existing URL, and host-level SPA fallback because it demands server configuration. React 19 is bundled into the theme and never peered, so the Frame cannot collide with the React that `@fractality/react` peers into the Preview iframe; Preact was rejected because `preact/compat` aliasing would repeat the dual-package hazard this repo has already paid for twice (ADR 0002, and the `instanceof Theme` breakage recorded in `TODO.md`). Trade-offs accepted: a breaking major with a hard cutover and no dual rendering path, mandelbrot's views obsolete, no-JS unsupported, and `file://` no longer usable because browsers give such pages an opaque origin and block every fetch — a real regression against today's build.
