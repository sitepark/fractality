- [ ] Convert to Typescript
    - **The client-rendered-Frame effort makes the first down payment** (decided 2026-08-17, see `.scratch/client-rendered-frame/`): the new CSR code is written in TypeScript, `@fractality/web` converts wholly and gains its first build step, and the type boundary stops at the payload contract so `@fractality/core` and the adapters stay JavaScript. That deliberately avoids the mixin layer rather than solving it, so the note below still stands for everything else — but the entry point changes: the repo will already have TypeScript, a tsconfig and a `tsc --noEmit` gate, so a later conversion starts from infrastructure rather than from nothing. One hard constraint discovered there and worth knowing before converting any other package: **Node refuses to strip types for files under `node_modules`** (`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`, verified on 24.12.0), so any package that goes TypeScript must compile and publish `dist/` — raw `.ts` cannot be published the way this repo publishes raw `.js` today, and the failure appears only for consumers.
    - Not realistic as a single pass. Recommended path: enable `allowJs`/`checkJs` with JSDoc types first (catches real bugs without a syntax rewrite — this is how several bugs fixed on 2026-08-14 would have been caught statically, e.g. an undefined variable inside a `catch` block, and `module.exports` used inside an ESM-only file). Convert leaf modules with no mixin dependency first (`utils.js`, `resolver.js`, `data.js`). Convert or hand-write `.d.ts` for the `packages/core/src/mixins/` layer last — it's the highest-effort, highest-risk part (see the mixin-system note above).
