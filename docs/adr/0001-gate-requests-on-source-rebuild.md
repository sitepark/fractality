# Gate incoming requests on in-progress source rebuilds

When a watched file changes, a source rebuilds its component tree (`_parse()` then `_resolveTreeContext()`), and publishes the newly parsed entities into the live collection partway through that rebuild — before their context has finished resolving. HTTP requests previously read straight from the live tree with no gating, so a request landing in that window could render a component with an empty or partially-resolved context. Rather than restructure the build pipeline to make the internal publish step atomic (a much larger, riskier change touching the recursive tree construction in `_parse()`), we added `Source#whenIdle()` / `Fractality#whenIdle()`, backed by the `_loading` promise that already spans the full rebuild, and made the web server await it before handling each request. Trade-off: a request arriving mid-rebuild now waits (typically milliseconds) for the rebuild to finish, instead of being served instantly with a chance of reading corrupted data.
