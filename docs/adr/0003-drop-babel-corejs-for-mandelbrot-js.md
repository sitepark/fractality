# Drop Babel/corejs transpilation for the mandelbrot theme's JS

The webpack build ran the theme's first-party JS (`node_modules` excluded) through `babel-loader` with `preset-env` + `corejs` 3, targeting `browserslist: defaults`. Before dropping it for the Vite migration, we checked what `defaults` actually resolves to today (no IE, but it does include KaiOS and `op_mini`) and grepped `assets/js/**` for syntax or runtime APIs that would need transpiling or polyfilling for those targets specifically — optional chaining, nullish coalescing, private class fields, `Array.prototype.flat`, `Object.fromEntries`, `Promise.allSettled`, and similar. None are used anywhere in the theme's own code; it only relies on long-safe ES2015+ features (classes, arrow functions, template literals). That means Babel+corejs was already a no-op for this codebase's actual output. Rather than carry the tooling forward as insurance against hypothetical future syntax, we dropped `@babel/core`, `@babel/preset-env`, `@babel/eslint-parser`, `babel-loader`, and `caniuse-lite` as direct dependencies of this package and rely on Vite/esbuild's default `build.target`. If a future change introduces syntax that doesn't run on a target we still care about, that's the trigger to reintroduce transpilation deliberately — not something to guard against speculatively now.
