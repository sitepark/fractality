# Inject a unique custom property per skin to avoid Rollup's content-based asset dedup

`blue.scss` and `default.scss` (and potentially other skin pairs, now or in the future) share identical color variables and therefore compile to byte-identical CSS. Discovered during the Vite migration that Rollup's asset emission deduplicates assets with identical content onto a single physical file regardless of the distinct names requested for each — with no filename hashing (a hard requirement here, since `theme.js` hardcodes exact asset paths), this silently dropped `default.css` from the build entirely while `blue.css` was written. `dist.spec.js` didn't originally catch this because it only checks that each skin's expected CSS file exists, which we verified passes once the fix is applied; the bug was found via an empirical scratch build during the migration, not something dist.spec.js flagged after the fact. We considered patching this post-hoc in a Rollup `generateBundle` hook (detect a missing expected filename, re-emit it under an explicit `fileName` to bypass Rollup's dedup path) but instead made every skin's compiled CSS genuinely unique by injecting `:root { --sp-mandelbrot-skin: "<name>"; }` via Vite's `css.preprocessorOptions.scss.additionalData`, keyed off each file's own name. This guarantees no two skins can ever collide again, regardless of what colors they happen to share, without any custom bundle-patching logic — and the injected custom property is itself a small legitimate feature (CSS can introspect which skin is active).
