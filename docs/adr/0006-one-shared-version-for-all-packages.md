# One shared version for all packages

The packages were versioned independently by lerna, each with its own tag (`@fractality/core@0.7.0`), its own `CHANGELOG.md` and its own GitHub release. In practice they were never released apart: every run of the release workflow shipped (nearly) all of them, because a change in `@fractality/core` or `@fractality/fractality` bumps every adapter that depends on it, and Dependabot touches most `package.json` files at once. Of 106 package releases up to 2026-10-22, 43 contained no change of their own, and their notes read only "Version bump only". Each release produced eight tags and eight GitHub releases, the "Latest" badge landed on whichever was created last, and finding out what a release contained meant reading eight changelogs. Independent versions bought nothing in exchange: nobody picks `@fractality/twig` 1.7 to go with `@fractality/core` 0.6. So all packages now share one version (lerna's fixed mode, forced to bump every package each time) with one `v*` tag, one GitHub release and one root `CHANGELOG.md`. The changelog, the release notes and the bump are rendered by git-cliff, configured to group by type and show the scope per line, which is what tells readers which package a change belongs to once there is only one changelog. Deciding the bump with git-cliff as well, rather than lerna's own conventional-commits support, keeps the version and the notes computed from the same commits; lerna only writes the version into the `package.json` files and publishes. The cost is a one-time jump: the shared version has to start above the highest existing one (nunjucks 2.5.0), so core goes from 0.7 to 3.0 without a breaking change, and from then on every release republishes every package. The adapters' peer ranges on fractality were widened to `< 4` rather than moved to `workspace:^`, because lerna rewrites a `workspace:` range in only one dependency field per package and nunjucks, react and twig list fractality as both a dev and a peer dependency, so their peer range would have shipped as a literal `workspace:^`; a check in the release workflow catches a major release that outgrows those ranges. The publish-before-push ordering from [ADR 0005](0005-publish-to-npm-before-pushing-release-tags.md) is unchanged; only the GitHub release step it mentions is now a single `gh release create`.
